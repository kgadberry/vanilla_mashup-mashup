# Vanilla Mashup Mashup

A client resource pack built by merging other packs from Modrinth.
No original artwork — see `credits.txt` for the full list, authors and licences.

## Layout

| File | What it is |
| --- | --- |
| `sources.json` | Which paths to take from each source zip, in merge order. Consumed by `build.py`. Its `sources` keys are filenames in `packs/`. |
| `build.py` | Runs `fetch.py sync`, then merges the source zips (+ `extra_files`) into one output zip. Deep-merges `.json`/`.mcmeta`; later sources overwrite earlier for everything else. |
| `fetch.py` | Pins each source zip to an exact Modrinth version and re-downloads them into `packs/` reproducibly. |
| `upstream.lock.json` | Generated by `fetch.py` — the pinned version + SHA-512 of every source. **Commit this.** |
| `packs/` | The downloaded source zips. Disposable, git-ignored — `fetch.py sync` rebuilds it from the lock. |
| `pack.mcmeta`, `pack.png`, `credits.txt` | `extra_files`, added last so they win any conflict. |

## Building the pack

```bash
python build.py "Vanilla Mashup Mashup.zip"            # syncs packs/ first, then merges
python build.py --no-sync "Vanilla Mashup Mashup.zip"  # merge only (offline / iterating)
```

Reports every merged file, every overwrite conflict, and any `sources.json`
path that matched nothing.

## Managing the sources

```bash
python fetch.py status              # locked version + packs/ drift, per pack
python fetch.py sync                # download anything missing or stale into packs/ (default command)
python fetch.py update [slug ...]   # re-pin to newest version that still lists MC 26.2
python fetch.py lock [--relock]     # (re)resolve zips in packs/ -> Modrinth versions by hash
python fetch.py pin KEY SLUG [VER]  # lock one entry by hand (modified zip / not on Modrinth)
```

Typical update cycle: `fetch.py update` → `python build.py out.zip` (auto-syncs) → test in game → commit `upstream.lock.json`.

`status` flags packs whose pinned version does not list `26.2` in its Modrinth
metadata (`no-26.2`). Most still work fine on 26.2 — it just means the author
has not re-tagged; it is a hint for where `update` might help, not an error.

`--game-version` (default `26.2`) overrides the target everywhere, e.g.
`python fetch.py --game-version 26.3 update`.

### Notes

- `fetch.py` needs network access and uses only the Python standard library.
- Every download is verified against the SHA-512 Modrinth publishes for the file.
- The lock key is the `sources.json` key and is a stable identifier: the file
  is written to `packs/<key>` even if Modrinth's own filename changes, so
  `build.py` keeps working across version bumps. `status` shows `mr:<name>`
  when Modrinth's filename has drifted.
- Fresh checkout: `python build.py out.zip` populates `packs/` from the lock on
  its own. To fill `packs/` without building, run `python fetch.py sync`.
