# Vanilla Mashup Mashup

A client resource pack built by merging other packs from Modrinth.
No original artwork — see `credits.txt` for the full list, authors and licences.

## Layout

| File | What it is |
| --- | --- |
| `sources.json` | Which paths to take from each source zip, in merge order, plus per-file `transforms` and loose `extra_files`. Consumed by `build.py`. Its `sources` keys are filenames in `packs/`. |
| `build.py` | Runs `fetch.py sync`, then merges the source zips (+ `transforms`, + `extra_files`) into one output zip. Deep-merges `.json`/`.mcmeta`; later sources overwrite earlier for everything else. |
| `fetch.py` | Pins each source zip to an exact Modrinth version and re-downloads them into `packs/` reproducibly. |
| `upstream.lock.json` | Generated by `fetch.py` — the pinned version + SHA-512 of every source. **Commit this.** |
| `packs/` | The downloaded source zips. Disposable, git-ignored — `fetch.py sync` rebuilds it from the lock. |
| `pack.mcmeta`, `pack.png`, `credits.txt` | `extra_files`, added last so they win any conflict. |

## Building the pack

```bash
python build.py "Vanilla Mashup Mashup.zip"            # syncs packs/ first, then merges
python build.py --no-sync "Vanilla Mashup Mashup.zip"  # merge only (offline / iterating)
```

Reports every merged file, every overwrite conflict, any `sources.json` path
that matched nothing, and every applied transform.

## Patching individual files

Some upstream packs need a small fix that isn't worth forking: a typo'd
filename, an image far larger than its detail warrants, or a handful of bad
lines in a text file. `sources.json`'s `transforms` list patches one file as
it comes out of a specific source archive, so the fix lives in
`sources.json` instead of a hand-built copy of the file committed to this
repo:

```json
"transforms": [
    {"source": "SomePack.zip", "path": "assets/minecraft/textures/a b.png",
     "rename": "assets/minecraft/textures/a_b.png"},
    {"source": "SomePack.zip", "path": "assets/minecraft/textures/huge.png",
     "resize": [512, 512]},
    {"source": "SomePack.zip", "path": "assets/minecraft/optifine/ctm/_overlays/x/x.properties",
     "patch": [{"find": "\\bold_id\\b", "replace": "new_id"},
               {"find": "\\bredundant_id\\b", "replace": ""}]}
]
```

Each entry needs `source` (a `sources.json` key) and `path` (the file inside
that archive), plus one or more of:
- `rename`: a new path — moves the file within the merge
- `resize`: `[width, height]` — re-encodes the image at this size (needs
  ImageMagick's `magick` or `convert` on `PATH`)
- `patch`: a list of `{"find", "replace"}` regexes run in order over the
  file's text (UTF-8) via `re.sub` — use `\b` for whole-word matches, and
  `""` as `replace` to delete a match

The file is taken regardless of that source's own include/exclude paths, and
is skipped under its original name in the normal merge — a rename never
leaves the broken name behind too. It still participates in
later-source-wins like any other entry, and `build.py` warns (without
failing the build) if a declared transform's `path` is missing from its
`source` archive, or if a `patch` rule's `find` matches nothing — both
usually mean the upstream pack changed and the transform needs updating.

## Managing the sources

```bash
python fetch.py status              # locked version + packs/ drift, per pack
python fetch.py sync                # download anything missing or stale into packs/ (default command)
python fetch.py update [slug ...]   # re-pin to newest version that still lists MC 26.2
python fetch.py lock [--relock]     # (re)resolve zips in packs/ -> Modrinth versions by hash
python fetch.py pin KEY SLUG [VER]  # lock one entry by hand (modified zip / not on Modrinth)
```

Typical update cycle: `fetch.py update` → `python build.py out.zip` (auto-syncs) → test in game → commit `upstream.lock.json`.

`status` flags packs whose pinned version does not list `26.2` in its Modrinth
metadata (`no-26.2`). Most still work fine on 26.2 — it just means the author
has not re-tagged; it is a hint for where `update` might help, not an error.

`--game-version` (default `26.2`) overrides the target everywhere, e.g.
`python fetch.py --game-version 26.3 update`.

### Notes

- `fetch.py` needs network access and uses only the Python standard library.
- `build.py` needs ImageMagick (`magick` or `convert` on `PATH`) only if
  `sources.json` has a `resize` transform; `rename`-only transforms and a
  plain merge need nothing beyond the standard library.
- Every download is verified against the SHA-512 Modrinth publishes for the file.
- The lock key is the `sources.json` key and is a stable identifier: the file
  is written to `packs/<key>` even if Modrinth's own filename changes, so
  `build.py` keeps working across version bumps. `status` shows `mr:<name>`
  when Modrinth's filename has drifted.
- Fresh checkout: `python build.py out.zip` populates `packs/` from the lock on
  its own. To fill `packs/` without building, run `python fetch.py sync`.
